# Mission 9 – Reflection

Completing Laboratory 9 helped me understand the importance of automation in cloud computing. When managing hundreds of cloud servers, performing tasks manually takes a lot of time and can lead to human errors. Automation makes these tasks faster and more consistent. Using Bash scripts and Cron jobs, administrators can schedule repetitive tasks such as backups without needing to execute commands manually every time.

However, automation also has potential dangers. A small mistake or destructive command inside a script can damage or delete important files. For example, if a script containing an incorrect command is executed on 1,000 servers, it could affect all those systems and cause serious problems. This is why scripts should be carefully checked and tested before being used on multiple servers.

Writing a Bash script was different from creating a Docker Compose YAML file in Laboratory 6. In Bash scripting, I used commands and variables to automate tasks step by step. In Docker Compose, I used a YAML file to define and manage application services such as Nextcloud and MariaDB. Both tools help reduce manual work, but they serve different purposes in cloud computing.

Looking back at my GitHub portfolio from Laboratory 1 to Laboratory 9, I can see how my understanding of cloud computing has improved. I learned about cloud infrastructure, containers, application deployment, data management, system operations, security, and automation. Each laboratory helped me develop new technical skills and understand how different cloud technologies work together.

The role I enjoyed most was the Cloud Deployment Engineer because I liked learning how to deploy applications and connect different services using Docker Compose. Overall, Laboratory 9 taught me that automation is an important skill for managing cloud environments efficiently, but it must always be used carefully and responsibly.
